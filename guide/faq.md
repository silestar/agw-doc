# 常见问题

## 请求返回 500，日志显示 "no available channel"

**原因**：所有渠道都不可用，或请求的模型在所有渠道中都不存在。

**排查**：
1. 检查渠道状态是否 "active"
2. 检查请求的模型是否在渠道的模型列表中
3. 查看日志中的 `retry_chain` 字段，了解每个渠道失败的原因

## 为什么我的请求走了不是优先级最高的账号？

可能原因：
1. 优先级更高的账号状态为 disabled/cooling
2. 优先级更高的账号不持有所请求的模型
3. 存在粘性绑定：上次这个消费者+模型走了某个账号，在 TTL 内会复用

## 设置了权重，流量分配不按比例？

权重是概率性的。短时间小流量看不出明显比例，长时间大流量趋近权重比。

## 账号频繁被禁用

检查日志中的禁用原因：
- `401` → API Key 无效/过期
- `429` → 上游限流，降低调用频率
- 关键词匹配 → 账号被封/欠费，联系上游

可以在 `config.yaml` 中调整：
- `probe_cooldown_duration`：冷却时间（默认 2 小时）
- `max_consecutive_downtimes`：进入更长冷却的阈值

## Redis 必须安装吗？

不必须。Redis 可选，不安装时：
- 配额计数回退到数据库（精度降低）
- 粘性绑定使用内存缓存（重启丢失）
- 系统仍正常工作，建议生产环境安装

## 管理面板可以公网访问吗？

**不建议**。管理面板包含敏感操作（创建 Key、管理账号）。请：
- 使用 Nginx 反向代理限制 IP
- 配置强密码
- 考虑使用 VPN 访问

## 插件的安全风险？

AGW 的插件系统设计为进程隔离：
- 插件以独立进程运行，崩溃不影响主系统
- 通信仅限于 `127.0.0.1`
- Token 认证
- 权限框架限制数据访问范围

但仍需注意：只安装可信来源的插件。

## 并发支持？

AGW 本身无硬性并发限制，性能取决于：
- Go runtime 的 goroutine 调度
- 上游 API 的并发限制
- 消费者的 RPM/TPM 配额

实测单实例可支撑数千并发请求。
