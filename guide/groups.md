# 分组与路由

## 分组体系

AGW 有两类分组，互相配合实现权限控制 + 流量分发：

```
消费者分组（Key Groups）         渠道分组（Channel Groups）
     │                              │
     │  绑定                        │
     └────── 中间连接 ──────────────┘
```

## 消费者分组

把多个消费者打包管理：

- 批量设置配额（RPM/TPM）
- 统一控制可访问的渠道范围
- 分组绑定到渠道分组，实现"分组 A 只能用渠道分组 X"

**操作**：管理面板 → 分组管理 → 消费者分组

## 渠道分组

把多个渠道打包做流量分发：

```
渠道分组 "high-quality":
  OpenAI 渠道: weight=50
  Azure 渠道: weight=30
  DeepSeek 渠道: weight=20
```

同一渠道可以属于多个分组。

**操作**：管理面板 → 分组管理 → 渠道分组

## 绑定关系

```
消费者分组 ── 绑定 ── 渠道分组

消费者分组 "VIP":
  消费者: 张三、李四
  绑定渠道分组: "high-quality", "backup"

→ 张三和李四可以使用 "high-quality" 和 "backup" 下的所有渠道
```

## 路由流程（完整版）

```
请求到达(model=gpt-4)
  → 解析 Consumer Key
  → 定位消费者分组 "VIP"
  → 查找绑定的渠道分组 ["high-quality", "backup"]
  → 遍历所有渠道分组
    → 遍历每个分组下的渠道（按权重排序）
      → 检查渠道是否有 gpt-4 模型
      → 账号池选号
      → 转发请求
      → 失败? 下一个渠道
  → 所有渠道都失败? 返回 500
```

## 最佳实践

1. **VIP 分组**：绑定高质量渠道，配额高
2. **基础分组**：绑定性价比渠道，配额适中
3. **备份分组**：绑定额外渠道，作为故障转移兜底
4. **避免过度嵌套**：一般 1-2 层分组足够
