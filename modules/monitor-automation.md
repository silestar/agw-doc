# 渠道监控与自动处置

## 设计动机

人工盯着管理面板看渠道状态不是长久之计。AGW 在 v0.1.4 引入自动监控定时任务（Cronjob），在 v0.3.3 完善为四级分类处置策略。

## 巡检频率

定时任务 `agw monitor run`（默认每 5 分钟执行一次）：

```
cron: */5 * * * *  agw monitor run
```

## 四级自动处置

| 级别 | 条件 | 行为 | 恢复 |
|------|------|------|------|
| 渠道无模型 | `channel_models` 为空（连续 N 次） | 自动禁用渠道 | 手动启用后自动同步 |
| 渠道全部账号故障 | 所有账号 status=disabled | 自动禁用渠道 | 账号恢复后自动启用 |
| 单个账号故障 | 单账号连续失败达到阈值 | 禁用该账号 | 进入冷却→按需探测恢复 |
| 全部渠道不可用 | 所有渠道都 disabled | 发送告警（面板 + 日志） | 需人工介入 |

## 配置项

```yaml
monitor:
  channel_empty_model_threshold: 3    # 无模型N次后禁用
  channel_all_disabled_threshold: 1   # 全账号故障后禁用
  notify_on_all_offline: true         # 全部离线时告警
```

## 恢复策略

- **渠道自动恢复**：当被禁用的渠道下任意账号恢复为 active 时，自动启用渠道
- **定时全量同步**：每日凌晨对活跃渠道执行一次全量模型同步

## 日志记录

每次巡检生成结构化日志，记录：
- 检查项、决策、执行时间
- 被处置的渠道/账号 ID
- 处置原因

## 手工干预

管理员可随时通过管理面板手动执行：
- 重置账号状态（force active）
- 强制启用/禁用渠道
- 触发模型同步
- 执行单次巡检
