# 插件管理器

## 管理职责

插件管理器负责插件的**全生命周期**：

```
注册 → 验证 → 加载 → 启用 → 调度 → 监控 → 停用 → 卸载
```

## 五大钩子调度

| 钩子 | 触发点 | 调度方式 |
|------|-------|---------|
| `pre_request` | 认证后、路由前 | 同步依次调用 |
| `post_response` | 上游响应后 | 同步依次调用 |
| `account_select` | 账号选择前 | 同步依次调用 |
| `on_log` | 请求结束 | **异步**不阻塞 |
| `connection_decorator` | TCP 连接建立 | 特殊：首插件生效 |

## 声明式钩子注册

v2.0 新设计，彻底废除 `channel_plugin_settings` 表：

- 插件在 `manifest.json` 声明 `hooks: ["pre_request", "post_response"]`
- 安装后自动注册到对应钩子调度链
- 不需要渠道级绑定
- 管理员只能启用/禁用钩子，不能新增

## 插件生命周期

```
注册（创建 DB 记录生成 Token） 
  → 验证（启动进程 + 健康检查） 
  → 加载（读取 manifest，注册钩子） 
  → 运行（接收钩子调用）
  → 停用（发送 SIGTERM）
  → 卸载（删除 DB 记录 + 清理文件）
```

## 故障处理

| 故障 | 行为 |
|------|------|
| 插件调用超时（默认 5s） | 跳过该插件，不阻塞请求 |
| 插件进程崩溃 | 自动重启（可配次数上限） |
| 插件返回非预期状态码 | 日志记录 + 跳过 |
| 连续崩溃达到上限 | 自动停用该插件 |

## 插件权限框架

11 个细粒度权限项，两级数据通道全覆盖：

- **TriggerHook 通道**：`filterHookRequest` 根据授权置零字段
- **CONNECT 通道**：根据授权决定是否传递 `X-AGW-*` 头

高敏感权限（`request_headers`、`channel_config`）授予需二次确认。
