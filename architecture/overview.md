# 总体架构

## 一句话说清楚

AGW 是一个放在你的应用和 AI 服务商之间的**智能中间人**。你只需像调用 OpenAI 一样调用 AGW，AGW 会根据配置自动选择最合适的渠道和账号来转发请求。

## 四层架构

```
┌─────────────────────────────────────────────┐
│                   接入层                       │
│          Gin Router (HTTP/SSE)               │
├─────────────────────────────────────────────┤
│                 业务服务层                     │
│  密钥管理  │  智能路由  │  账号池  │  统计分析   │
├─────────────────────────────────────────────┤
│                 渠道适配层                     │
│  OpenAI  │  Anthropic  │  Gemini  │  自定义   │
├─────────────────────────────────────────────┤
│                 基础设施层                     │
│  SQL DB  │  Redis  │  文件系统  │  插件管理    │
└─────────────────────────────────────────────┘
```

## 一个请求的完整旅程

```
用户 → [Gin Router] → 认证(消费者 Key) → 分组路由
  → 选择渠道 → 账号池选号 → 渠道适配器协议转换
  → 上游 AI → 响应返回 → 日志记录 → 用户
```

如果某一步失败（账号挂了、渠道不可用），AGW 会自动重试下一个可用资源，并完整记录重试链路。

## 技术选型

| 选择 | 理由 |
|------|------|
| **Go** | 高并发、低内存、单二进制部署 |
| **Gin** | 轻量 HTTP 框架，性能好 |
| **GORM** | 多数据库方言（SQLite/MySQL/PG）统一接口 |
| **Vue 3 + Naive UI** | 现代化管理面板，TypeScript 类型安全 |
| **Sidecar 插件** | 进程隔离，插件挂了不影响主系统 |
| **AES-256-GCM** | 保护 API Key 等敏感数据 |

## 安全设计

- 所有上游 API Key 使用 AES-256-GCM 加密存储
- `SECRET_KEY` 首次启动自动生成，持久化到 `.env`
- 管理面板展示脱敏 Key（`sk-abc****`）
- 插件 Sidecar 绑定 127.0.0.1，Token 认证
- UID 隔离：插件进程以受限用户运行，无法访问数据库
