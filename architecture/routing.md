# 智能路由机制

## 四层路由模型

AGW 的路由不是简单的"随机选个渠道"，而是**层层收敛**：

```
消费者 → 消费者分组 → 渠道分组 → 渠道账号
  ↓         ↓           ↓         ↓
 认证    权限控制     流量分发   负载均衡
```

每层都有明确的决策规则，最终指向一个确定的账号。

## 确定性路由

> **相同输入永远指向相同账号，不随机。**

这样设计的好处：
- 上游 API 有**语义缓存**（相同 prompt 命中缓存更便宜），复用同一账号能最大化缓存命中
- 出问题时方便排查（知道请求走了哪个账号）

## 权重分配

同一渠道分组下多个渠道时，按**权重比例**分配流量：

```
渠道A: weight=70
渠道B: weight=30
→ 70% 流量走渠道A，30% 走渠道B
```

## 模型存在性过滤

这是 AGW 路由的特色功能。请求 `gpt-4` 时：
- 自动检查每个渠道的 `channel_models` 表
- 没有 `gpt-4` 的渠道**静默跳过**
- 避免"选了渠道才知道不支持该模型"的失败

## 路由流程图

```
request(model=gpt-4) 
  → 定位消费者分组 
  → 查找绑定的渠道分组 
  → 遍历渠道(权重排序) 
    → 检查模型存在性 
    → 账号池选号 
    → 转发请求
    → 失败? 重试下一个渠道
```

## 与账号池的协作

路由选定渠道后，交给账号池做"微调"——在同渠道的多个账号中选择最优的一个。账号池的优先级、粘性、健康状态都会影响最终选择。
