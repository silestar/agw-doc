# 插件架构

## Sidecar 模式

```
┌──────────────────┐       HTTP        ┌──────────────────┐
│   AGW 主进程     │ ←───────────────→  │   插件进程        │
│  (Gin Router)   │  Authorization     │  (HTTP Server)    │
│                  │  Bearer Token      │                   │
│  管理面板 ←→ 插件 │                    │  实现钩子端点       │
│  管理             │                    │                   │
└──────────────────┘                    └──────────────────┘
```

## 关键设计

### 进程隔离

- 插件以**独立进程**运行
- 插件崩溃不影响 AGW 主系统
- AGW 通过超时机制防止插件阻塞请求

### 通信地址

插件监听 `127.0.0.1:<port>`（仅本地回环），不暴露到网络。AGW 通过注册时分配的端口号调用插件。

### 进程生命周期

AGW 负责管理插件进程：
- `start`：启动进程，注入环境变量（含 `PLUGIN_AUTH_TOKEN`、`PLUGIN_PORT`）
- `stop`：发送 SIGTERM，等待优雅退出
- `restart`：先停后启

### 启动流程

```
AGW 注册插件 → 生成 AUTH_TOKEN → 分配端口 
  → 启动插件进程（注入环境变量）
  → 健康检查 GET /health → 200 OK
  → 验证 manifest.json 
  → 注册钩子 → 插件就绪
```

## 资源限制

| 项目 | 限制 |
|------|------|
| 钩子调用超时 | 5 秒（可配） |
| 最大重启次数 | 3 次/5 分钟 |
| 监听地址 | 127.0.0.1 only |
| 内存/CPU | 依赖 Docker 资源限制 |
